## 1. 🔴 먼저 — 3단계가 손님을 막을 뻔했습니다

3단계 코드는 `不用`(인명 불가)을 목록에서 **뺐습니다.** 대표님이 DB 에서 재보신 결과 —

```
전체 8,650자 중 不用 4,486자 (51.9%)

485개 음(音) 가운데
  A. 후보 0개   ★50개 음    겁 곪 곯 괴 굄 굅 궤 긱 깁 넉 넘 넣 늠 …
  B. 1~2개       101개 음
  C. 3~5개       110개 음
  D. 6개 이상    224개 음
```

그리고 이유를 확인했더니 **글자가 없어서가 아니라 있는 글자가 전부 `不用`** 이었습니다.

```
겁  전체 5자   劫 刦 刧 佉 迲   전부 不用
괴  전체 15자  乖 佹 拐 傀 塊 …  전부 不用
늠  전체 5자   蒙 凛 廩 懍 澟   전부 不用
```

★**덕암 자료가 옳습니다.** 그 음의 글자들이 인명에 맞지 않는 뜻인 것입니다.

⚠️ **그런데 「내 이름 풀이」는 이미 그 이름을 가진 분이 오는 화면입니다.**
거르면 그분은 한자를 하나도 못 골라 「이름 풀이 보기」 단추가 영영 안 눌립니다.

### 고침 — 「거르기」를 「표시하기」로

```
정말로 막는 것    avoid_hard · 쉬는 줄(is_active=false)     — 아주 좁게
보여 주되 표시     不用 · 무거운 뜻                          — 흐리게 + 배지
추천에서는 뒤로    softPenalty  (不用 40 · 뜻 25 · 평범 0)
```

### 실측 — 막히는 음이 0 이 됐습니다

```
❌ 3단계 (거르기)      후보 0개인 음  38개  8.2%
✅ 3단계-b (표시하기)   후보 0개인 음   0개  0.0%

흐리게 + 배지로 나가는 글자   1,526자  29.9%
목록에서 «정말로» 빠지는 글자      0자
```

⚠️ `diagnosis` 화면은 원래부터 「아래 글자들은 일반적으로 이름에 잘 쓰지 않아요」 구획으로
따로 보여 주고 있었습니다. **그 방식이 옳았고**, 개명 화면 둘을 거기에 맞췄습니다.

## 2. 별점 ★2.5~5.0

### ⚠️ 먼저 — 주신 공식과 라벨표가 어긋납니다

지시서의 `ROUND(Score / 100 * 10) / 2` 를 그대로 계산해 라벨표와 대조했습니다.
**17개 표본 가운데 14개가 어긋났습니다.**

```
점수   공식      라벨표
 90    ★4.5  ≠  ★5.0
 75    ★4.0  ≠  ★4.5
 60    ★3.0  ≠  ★4.0
 45    ★2.5  ≠  ★3.5
  0    ★0.0  ≠  ★2.5    ← 공식에는 하한이 없습니다
```

공식대로 하면 **손님 화면에 ★0.0·★1.0 이 나옵니다.** 하한을 두라는 지시의 취지와 어긋나므로
**라벨표를 기준으로 삼았습니다.** 공식 쪽이 맞다고 보시면 `starRaw()` 로 바꾸시면 됩니다(한 줄).

### 확정된 표

| 점수 | 별 | 말 |
|---|---|---|
| 90~100 | ★5.0 | 매우 조화로움 |
| 75~89 | ★4.5 | 우수함 |
| 60~74 | ★4.0 | 좋음 |
| 45~59 | ★3.5 | 보통 · 살펴볼 자리 |
| 30~44 | ★3.0 | 참고 · 보완 권장 |
| 0~29 | ★2.5 | 살펴볼 자리가 여럿 |

하한을 ★3.0 → **★2.5** 로 내리시며 낮은 칸을 둘로 갈랐습니다.
⚠️ 말은 여전히 단정이 아닙니다 — 흉·불길·나쁨을 쓰지 않습니다.
「자리가 여럿」은 «몇 군데를 함께 보자» 는 뜻입니다.

### 용신 하한

```
이름(성 제외)에 용신이 주 자원오행으로 담기면
  → «사주와의 만남» 별점이 ★3.5 아래로 안 내려갑니다
  → 10점이어도 ★3.5 · lifted=true 로 표시됩니다
```

⚠️ 지시에 「최소 ★3.5(60점)」이라 적혀 있는데 라벨표에서 60점은 ★4.0 입니다.
**별 값(★3.5)을 따랐습니다.** ★4.0 으로 올리시려면 `YONGSIN_FLOOR` 한 줄입니다.

⚠️ 하한은 **«사주와의 만남» 에만** 겁니다. 자원오행에는 안 겁니다(지시서 그대로).

### 관점 다섯의 점수 출처

```
④ 자원오행       judgeResource.breakdown.flow  / 30       ★정밀 (0~100)
⑤ 사주와의 만남   (yongsin + balance)          / 70       ★정밀 (0~100)
① 음양 ② 발음 ③ 수리   diagnoseName 의 3단 등급 → 80/52/40
```

⚠️ ①②③은 아직 3단이라 별이 **★4.5 · ★3.5 · ★3.0 세 가지뿐**입니다.
`precise: false` 로 표시해 두었으니 화면에서 다르게 그리셔도 됩니다.
정밀하게 하려면 `scoreSuri`·`scoreSound` 를 고쳐야 하고 그건 4단계입니다.

## 3. ⚠️⚠️ 방침이 바뀌는 자리입니다 — 알고 쓰십시오

`naming.ts:8` 에 대표님이 세우신 방침이 있습니다.

> 「"좋다/나쁘다" 판정하지 않는다. **화면엔 등급(grade)을 노출하지 않는다.**」

**별점은 등급입니다.** 화면에 붙이는 순간 이 방침이 바뀝니다.

다만 지시하신 라벨표는 그 취지를 지키도록 설계돼 있습니다 —
하한이 있어 ★1.0·★2.0 이 나올 수 없고, 가장 낮은 칸의 말도 단정이 아닙니다.
**«가르는 등급» 이 아니라 «어느 쪽을 더 살펴볼지» 를 가리키는 눈금**입니다.

### AI 프롬프트는 건드리지 않았습니다

```
화면   별을 보여 줍니다
글     AI 는 여전히 「점수·등급·몇 점」을 말하지 않습니다 (프롬프트 그대로)
```

둘이 어긋나지 않습니다 — 별은 «눈금» 이고 글은 «서술» 입니다.
★AI 가 별을 언급하게 하려면 프롬프트를 고쳐야 하는데, **권하지 않습니다.**
지금까지 세 이름으로 확인한 겸손한 어조가 흔들립니다.

### 되돌리기

화면에서 별 컴포넌트만 빼면 예전 그대로입니다. 라우트가 `stars` 를 내려보내도
화면이 안 그리면 아무 일도 일어나지 않습니다.

## 4. 라우트가 내려보내는 것

```jsonc
{
  "result": …, "commentary": …,
  "stars": [
    { "key":"yinyang", "title":"음양오행", "star":4.5, "label":"우수함",
      "tone":"good", "score":80, "lifted":false, "precise":false },
    …
    { "key":"yongsin", "title":"사주와의 만남", "star":3.5, "label":"보통 · 살펴볼 자리",
      "tone":"mid", "score":7, "lifted":true, "precise":true }
  ],
  "overallStar": { "star":4.0, "label":"좋음", "tone":"good", "score":63, "lifted":false }
}
```

⚠️ `score` 는 **진단용**입니다. 손님 화면에 숫자를 쓰지 마십시오 — 별과 말만 쓰십시오.

### 화면에 붙이는 법 (아직 안 붙였습니다)

`PerspectiveAccordion` 의 각 관점 제목 옆에 넣으시면 됩니다.

```tsx
import { starGlyphs } from '@/lib/saju/starRating'
const g = starGlyphs(s.star)
<span>{'★'.repeat(g.full)}{g.half ? '☆' : ''}{'·'.repeat(g.empty)} {s.label}</span>
```

★**일부러 안 붙였습니다.** 방침이 바뀌는 자리라 대표님이 화면을 보고 정하시는 것이 맞습니다.
붙여 드릴까요? 말씀해 주시면 `PerspectiveAccordion` 까지 만들어 드리겠습니다.
