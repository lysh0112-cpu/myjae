정비사업 조합원을 위한 행정지원 서비스 · 프론트엔드

배포 주소 : https://da-ara.pages.dev

세 파일은 **서로를 전혀 참조하지 않습니다.** 각각 혼자서 돌아갑니다.

### 왜 나눴나

| 이유 | 설명 |
|---|---|
| 보안 | 조합원 앱 소스에 관리자 코드가 한 줄도 없습니다. 소스를 열어봐도 관리 기능의 존재조차 알 수 없습니다 |
| 화면 크기 | 조합원은 폰, 관리 업무는 PC입니다. 한 화면에 억지로 담으면 양쪽 다 불편합니다 |
| 사고 방지 | 조합원 화면을 고치다가 관리 기능을 건드릴 일이 없습니다 |
| 권한 | 파일이 다르면 나중에 서버에서 접근 제어를 걸기도 쉽습니다 |

### 절대 어기면 안 되는 것

1. **직원 화면에 구역 전환을 넣지 마세요.** 미아3 직원이 미아2 자료를 보면 안 됩니다. 크로스테넌트 유출 1건이면 사업이 끝납니다.
2. **감사 로그를 끄는 기능을 만들지 마세요.** 조합이 "운영사가 우리 자료를 봤냐"고 물을 때 답할 수 있는 유일한 근거입니다.
3. **관리자 코드를 `index.html`로 되돌리지 마세요.** 편의를 위해 합치면 분리한 의미가 사라집니다.
4. **명부·감정평가는 직원 권한에서 계속 막아 두세요.** 조합장 결재를 거치게 하는 것이 조합과 운영사 양쪽을 지킵니다.

## 배포 방법

늘 하시던 순서 그대로입니다. 파일이 세 개로 늘었지만 **폴더째 덮어쓰면** 신경 쓸 게 없습니다.

```
① 받은 ZIP 압축 풀기
② da-ara-web 폴더를 C:\dev\da-ara 에 붙여넣기 → 파일 바꾸기
③ GitHub Desktop → Summary 입력 → Commit to main → Push origin
④ 1분 뒤 da-ara.netlify.app 새로고침
```

Netlify 설정은 그대로 두시면 됩니다.

```
Publish directory : da-ara-web
Build command     : (없음)
```

> **파일을 하나씩 옮기지 마세요.** 이름이 어긋나거나 폴더가 틀려서 시간을 많이 씁니다. 폴더 통째로가 안전합니다.

## 시연용 로그인

지금은 화면 안에서만 하는 검사입니다. **진짜 보안이 아닙니다.**

```
조합원      index.html      명부 100명 누구나 / 111111
조합 직원   admin.html      류승현2 / 111111
운영자      console.html    류승현 / 111111

전자결재    approval.html   류승현2   / 111111   담당자 (1단계)
                            박총무    / 111111   총무이사 (2단계)
                            김조합장  / 111111   조합장 (3단계)
                            류승현    / 111111   운영자
```

### 조합원 로그인 (가상 명부)

`roster-demo.js` 에 가상 조합원 100명이 들어 있습니다. **전부 가짜입니다.**

앱에서 `내정보 → 화면 미리보기 → 회원가입 화면 보기` 로 들어가서,
명부에 있는 **이름과 휴대폰번호**를 정확히 넣고 인증번호 칸에 **111111** 을 넣으면
그분의 자료(조합원번호·소유 물건·감정평가액·신청 평형)로 로그인됩니다.

명부에 없는 이름을 넣어도 화면은 열립니다. 그때는 예시 값이 표시됩니다.

명부는 조합 직원 화면(`admin.html` → 조합원 명부)에서도 볼 수 있지만,
**성명은 가려서, 연락처는 뒷자리만, 감정평가액은 아예 보이지 않습니다.**
전체를 보려면 조합장 결재가 필요하도록 만들어 두었습니다.

> **실제 명부를 `roster-demo.js` 에 넣지 마십시오.**
> 이 파일은 인터넷에 공개된 폴더에 있어 누구나 내려받을 수 있습니다.
> 진짜 명부는 Supabase 의 `daara_registry` 스키마에 두고,
> 서버 로그인을 거친 사람에게만 내려보내야 합니다.

개발 단계라 세 계정의 암호를 `111111` 로 통일했습니다. 암호는 소스에 그대로 적혀 있지 않고 되돌릴 수 없는 값(해시)으로만 들어 있습니다. 소스를 봐도 암호는 알 수 없습니다. 다만 마음먹고 뜯으면 화면은 열립니다.

> **조합에 계정을 나눠줄 때는 운영자 암호를 반드시 다른 값으로 바꾸십시오.**
> 직원 암호를 조합 사무실에 알려주는 순간, 같은 암호로 운영자 콘솔(전 구역·계정·감사 로그)까지 열립니다.

**조합원 명부와 감정평가 자료가 들어오기 전에 반드시 서버 로그인(Supabase Auth)으로 바꿔야 합니다.**

총회 안건과 전자투표, 집계 숫자는 **전부 예시**입니다. 표가 저장되거나 문자가 나가지 않습니다.

## 나중에 실제 자료를 넣을 때

### 총회 안건

`index.html` 에서 `총회 · 전자투표` 로 검색하면 나옵니다. `MEETING` 과 `AGENDA` 두 개만 고치면 됩니다.

의결 요건(가결 기준·직접출석 비율)은 안건마다 다릅니다. **조합 자문 변호사 확인을 받은 값만** 넣으십시오.

### 구역 · 계정 · 로그

`console.html` 의 `TENANTS` · `ACCOUNTS` · `AUDIT` 를 Supabase 조회로 바꾸면 됩니다.

### 총회 · 투표 (Supabase 대응)

| 화면 안의 이름 | 옮겨갈 테이블 | 내용 |
|---|---|---|
| `DEMO_MEETING` | `meetings` | 총회 마스터 · 상태(대기/진행중/마감) · 투표 기간 |
| `DEMO_MEETING.agendas` | `agendas` | 안건 · 의결여부 · 가결기준 · 모수 · 직접출석 비율 |
| `DEMO_VOTES` | `votes` | 전자·서면·현장 통합 로그 |
| `DEMO_WITHDRAWALS` | `withdrawals` | 철회 신청 · 서명확인 · 스캔 보완 |

`votes` 의 주요 컬럼은 `meeting_id` · `agenda_id` · `voter_id` · `vote_type`(electronic/written/onsite) · `choice`(yes/no/abstain) · `serial` · `status`(active/withdrawn) · `entered_by` · `verified_by` 입니다.

**집계는 `status = 'active'` 인 표만 셉니다.** 철회된 표는 지우지 않고 `withdrawn` 으로 남깁니다. 지운 기록은 나중에 아무것도 증명하지 못합니다.

**가결 모수는 문자열로 판단하지 마십시오.** `agendas.quorum_base` 를 `members`(전체 조합원) 또는 `attendees`(출석 조합원)로 명시합니다. "조합원 과반수"와 "출석 조합원 과반수"는 글자가 겹쳐서 문자열로 가르면 반드시 틀립니다.

### 전자결재 (Supabase 대응)

| 화면 안의 이름 | 옮겨갈 테이블 | 내용 |
|---|---|---|
| `CLASSES` | `doc_classes` | 분류 마스터 · 연도별 채번 일련번호 |
| `TEMPLATES` | `doc_templates` | 표준 품의문 양식 · 필수 증빙 목록 |
| `DOCS` | `documents` | 문서 본문 · 상태(pending/approved/rejected) |
| `DOCS[].line` | `doc_approvals` | 단계별 결재자 · 상태 · 시각 · 의견 |
| `DOCS[].files` | `doc_files` | 증빙 PDF (Supabase Storage 연결 필요) |
| `APPROVERS` | `doc_approvers` | 결재선 인원 · 단계 · 사용 여부 |

**문서 분류번호는 저장하는 순간 확정됩니다.** `[분류코드]-[발행연도]-[일련번호 3자리]` 형식이고, 이후에는 바뀌지 않습니다. 문서번호가 나중에 바뀌면 결재·보관·인용이 전부 어긋납니다.

**분류는 삭제하지 않고 `active = false` 로 둡니다.** 지우면 그 코드로 발행된 옛 문서의 분류번호가 미아가 됩니다.

**결재는 순차입니다.** 1단계가 승인해야 2단계가 열립니다. 반려되면 문서가 기안자에게 돌아가고 뒤 단계는 열리지 않습니다.

### 회계 자료 스프레드시트 내려받기

`admin.html` → `회계 집계` 아래쪽. **CSV로 내려받고 엑셀에서 바로 열립니다.**

| 파일 | 쓰는 곳 | 담긴 것 |
|---|---|---|
| 지출 내역서 | 세무사무소 | 건별 상세 · 공급가액 · 부가세 · 결재문서번호 · 날인대장번호 |
| 계정과목별 집계 | 결산총회 보고 | 과목별 합계 · 건수 · 비중 |
| 예산 대비 집행 | 구청 제출 | 예산 · 집행 · 잔액 · 집행률 |
| 결재 · 날인 이력 | 원본 대조 | 문서번호 · 증빙 파일명 · 날인대장번호 |

**세무사가 번호로 원본을 찾습니다.** 각 줄에 `CON-2026-008`(결재문서)과 `SEAL-0013`(날인대장)이 함께 적힙니다.

**부가세는 과세 건만 역산합니다.** 전자결재 기안에서 `과세 / 면세 / 불공제`를 고르게 했습니다. 임차료를 개인에게 내는 경우처럼 세금계산서가 없는 건에 일률적으로 10%를 떼면 틀린 세액이 나옵니다.

**금액에 쉼표를 넣지 않습니다.** 쉼표가 있으면 CSV 열이 밀리고 엑셀이 숫자로 읽지 못해 합계가 되지 않습니다. 파일 맨 앞에는 BOM을 붙여 한글이 깨지지 않게 했습니다.

**예산은 직원 화면에서 등록합니다.** `회계 집계` → `예산 등록`에서 계정과목별로 총회 승인 금액을 넣습니다. 집행률이 100%를 넘으면 주황색으로 표시됩니다.

### 전자동의서 징구

조합원 앱 `내정보` → `전자동의서`, 직원 화면 `동의서 징구`.

**동의서는 소송에서 가장 치열하게 다투는 서류입니다.** 조합설립 인가가 취소되는 사건은 대부분 여기서 시작합니다. 그래서 절차를 일부러 무겁게 잡았습니다.

```
① 요건 안내 모달을 먼저 읽힌다
② 서식을 끝까지 내려 본 뒤에야 동의 칸이 열린다
③ PASS 또는 NICE 인증을 반드시 거친다
④ 완료증에 시각과 서명값을 남긴다
```

**PIN · 생체로는 낼 수 없습니다.** 본인확인기관 식별값(CI)을 명부와 대조해야 타인 명의 도용을 막고 증거 능력이 섭니다. 코드에서도 `pass`/`nice`가 아니면 거부합니다.

**진입하면 안내 모달이 먼저 뜹니다.** 철회 제한 · 본인 제출 · 공유물건 대표 · 기록 보관 · 서면 병행 다섯 가지를 안내하고, 맨 아래에 이 문구가 고정돼 있습니다.

> ※ 본 양식 및 상세 징구 가능 요건은 추후 확정 후 보완 예정입니다.

법과 지침이 바뀌는 중이라 화면에 그대로 적었습니다. "된다"고 단정했다가 나중에 무효가 되면 조합이 다칩니다.

**완료증에는 서명값이 들어갑니다.** 접수번호 · 서식 · 제출자 · 지번 · 동의여부 · 시각 · CI를 묶어 계산한 값이라, **내용이 하나라도 달라지면 값이 바뀝니다.** 조합이 임의로 고쳤는지 이 값으로 확인할 수 있습니다.

**다시 제출하면 앞 기록은 지우지 않고 `대체됨`으로 남깁니다.** 고칠 수 있으면 증거가 되지 못합니다.

**인가 요건은 두 가지를 함께 봅니다.**

```
조합설립 동의   토지등소유자 3/4 이상  +  토지면적 1/2 이상
```

사람 수만 채우고 인가를 신청했다가 반려되는 일이 실제로 있습니다. 작은 필지 소유자가 많이 동의해도 면적 요건은 안 찰 수 있어, 직원 화면에서 두 막대를 나란히 보여줍니다.

제출 한 건마다 PASS 인증이 한 건씩 발생해 **이용 · 요금 화면과 운영자 콘솔 미터기에 바로 쌓입니다.**

### 서면 동의서와 결재

실제로는 **서면이 더 많습니다.** 어르신들은 종이로 내시고 조합 사무실에 직접 오십니다. 전자로만 받는 구조는 반쪽입니다.

**대장은 하나로 합치고 접수 방법만 구분합니다.** 따로 관리하면 같은 사람이 두 번 세어지고 요건 계산에서 헷갈립니다. 법적 효력은 같습니다.

```
조합원이 올 때마다   →  입력 + 스캔        (결재 대기로 쌓임)
기간이 차면          →  묶어서 결재 올리기  (전자 명단도 함께)
조합장 승인          →  대장 확정
```

**승인 전까지 대장에 반영되지 않습니다.** 서면은 직원이 입력하는 과정이 끼어들기 때문입니다. 전자는 PASS 인증과 서명값이 붙어 손댈 여지가 없지만, 최종 명단에는 함께 들어가야 하므로 결재 문서에 같이 붙습니다.

**스캔이 다 붙어야 결재를 올릴 수 있습니다.**

**제출일은 입력한 날이 아니라 종이에 적힌 날입니다.** 3월 2일에 낸 것을 3월 10일에 입력했다면 3월 2일이 기준입니다. 순서를 다툴 때 그 날짜로 판단합니다.

**접수번호를 종이 오른쪽 위에 적어 두십시오.** 나중에 구청이 특정 동의서를 찾을 때 바로 꺼낼 수 있습니다.

결재 문서에는 이렇게 올라갑니다.

```
CST-2026-001  조합설립 동의서 징구 명단 승인의 건
  전자 접수 31명 · 서면 접수 51명 = 82명 (동의 76명)
  사람 수  76 / 73     충족
  토지면적 8,648 / 5,844㎡  충족
  붙임 : 통합 명단 1부 · 서면 스캔 51부 · 전자 완료증 31부
※ 서면 원본은 조합 사무실 보관, 인가 신청 시 구청 제출
```

### 단체 문자 발송

`admin.html` → `단체 문자`. 세 걸음으로 나눴습니다.

```
수신자 고르기  →  메시지 작성  →  발송 확인  →  결과
```

**빠른 조건 선택** — 전체 / 의결권자 / 앱 미가입 / 투표 미참여 / 공유 물건. 검색으로 좁힌 뒤 `이 목록 전체 선택`도 됩니다.

**알림톡은 승인받은 템플릿만 보냅니다.** 문구를 마음대로 고치면 카카오가 발송을 거부합니다. 실무에서 가장 많이 걸리는 대목이라 화면에서 아예 막았습니다. 자유 문구는 SMS · LMS로 안내합니다.

**SMS는 90바이트까지입니다.** 넘으면 자동으로 LMS가 되고 단가가 15원에서 45원으로 세 배가 됩니다. 글자 수를 세어 `LMS 전환`이라고 미리 알려줍니다.

**보내기 전에 비용을 보여줍니다.**

```
보낼 건수  100    남은 제공량  120
기본 제공 안 100   추가 비용    0원
```

넘어가는 경우에는 몇 건이 초과되고 얼마가 더 나오는지 먼저 보여주고 확인을 받습니다.

**야간이면 예약을 권합니다.** 밤 9시~아침 8시에는 `아침에 보내기`와 `그래도 지금 보내기`를 함께 띄웁니다.

**`나에게 시험 발송`이 있습니다.** 100명에게 잘못된 내용이 나가면 되돌릴 수 없습니다.

**번호는 뒷자리만 보입니다.** 발송에는 전체 번호가 쓰이지만 화면에는 가려서 나옵니다. 누가 언제 누구에게 보냈는지 이력이 남고 지울 수 없습니다.

발송하면 **사용량 미터기에 즉시 쌓이고** `이용 · 요금` 화면과 운영자 콘솔에 함께 반영됩니다. 알림톡 실패분은 문자로 대체되어 문자 건수로 셉니다.

### 본인인증 (하이브리드 3단계)

```
1단계 · 최초 1회    PASS 또는 NICE → 명부 대조 → 세션 발급 (90일)
2단계 · 평상시      인증 없이 이용 (공지 · 자료실 · AI · 우리집)
3단계 · 의결 직전   투표함에 넣기 전 한 번 더
```

투표할 때마다 PASS를 부르면 조합원은 번거롭고 조합은 비용을 냅니다. 아무 확인 없이 받으면 대리 투표를 막을 수 없습니다. 그 사이를 잡은 구조입니다.

**재인증 등급**

| 무엇을 할 때 | 필요한 확인 | 과금 |
|---|---|---|
| 공지 · 자료실 · AI 질의 | 인증 없이 | — |
| 설문 · 일반 안건 투표 | PIN · 생체 | 없음 (기기 내 처리) |
| **시공자 선정 의결** | **PASS 필수** | 건당 |
| **동의서 제출** | **PASS 필수** | 건당 |

시공자 선정은 법이 조합원 과반수 직접 출석을 요구하는 안건이고, 동의서는 소송에서 가장 치열하게 다투는 서류입니다. PIN 여섯 자리로 끝내면 "본인이 아니었다"는 주장에 방어가 약합니다.

**안건 제목으로 자동 판정합니다.** `시공자` · `해임` · `동의서` · `합병` · `해산`이 들어가면 PASS를 요구합니다.

**세션은 세 경우에 끊깁니다** — 90일 경과 · 기기 변경 · **명부 변경**. 지분이나 대표조합원이 바뀌면 의결권도 달라지는데, 옛 세션이 남아 있으면 의결권 없는 분이 투표할 수 있습니다.

**인증 정보는 조합에 저장하지 않습니다.** 본인확인기관이 준 식별값(CI)만 받아 명부와 대조하고 버립니다.

연동은 **포트원**을 기본으로 잡았습니다. PASS · NICE · KCB를 한 번에 붙일 수 있습니다. 단가는 운영자 콘솔 `본인인증` 메뉴에서 고치며, **요금 화면의 같은 항목과 함께 바뀝니다.**

### 사용량과 요금

**기본료 안에 일정량이 들어 있고, 넘긴 만큼만 더 냅니다.** 평달에는 조합이 기본료만 내므로 예산을 세우기 쉽고, 총회가 있는 달에만 조금 더 나옵니다.

계량 대상 일곱 가지입니다.

| 항목 | 월 제공량 | 청구 단가 |
|---|---|---|
| 카카오 알림톡 | 500 | 15원 |
| 단문 문자 (SMS) | 200 | 15원 |
| 장문 문자 (LMS) | 50 | 45원 |
| 사진 문자 (MMS) | 10 | 130원 |
| 본인확인 PASS | 50 | 60원 |
| 본인확인 NICE | 50 | 65원 |
| AI 생성 답변 | 500 | 20원 |

기본료는 월 100,000원입니다. **단가와 제공량은 운영자 콘솔에서 직접 고칠 수 있고**, 고치면 모든 계산이 다시 됩니다.

**초과분은 달마다 따로 셉니다.** 분기 합계로 계산하면 제공량을 세 배로 준 셈이 되어 실제보다 적게 청구됩니다. 정산에서 가장 흔한 실수입니다.

**원가와 마진은 운영자 콘솔에서만 보입니다.** 조합 화면(`admin.html` → `이용 · 요금`)에는 묶음 청구 금액만 나갑니다.

**AI 답변을 눈여겨보십시오.** 건당 20원은 싸 보이지만 조합원이 자료실에서 자꾸 물어보면 문자보다 큰 비용이 됩니다. 조합 화면에서 초과 요금의 몇 %인지 따로 짚어 줍니다.

### 구역 고유번호 (tenant_id)

```
MIA-002   미아 2구역
JAN-001   장위 1구역
HEU-003   흑석 3구역
```

지역 3자리 + 구역번호 3자리입니다. **화면 표시값이 곧 데이터베이스의 `tenant_id`입니다.** 둘이 다르면 감사 로그를 볼 때마다 머릿속으로 변환해야 하고 언젠가 사고가 납니다.

| 어디에 | 어떻게 |
|---|---|
| DB 행 구분 | `tenant_id = 'MIA-002'` |
| 접근 제어(RLS) | `tenant_id = current_tenant()` |
| 파일 보관 | `storage/MIA-002/…` |
| 감사 로그 | `tenant=MIA-002` 기록 |

**한 번 정하면 바꾸지 않습니다.** 네 가지가 전부 이 값에 묶여 있습니다.

### 운영자 콘솔

| 메뉴 | 하는 일 |
|---|---|
| 회원사 현황 | 고유번호 · 조합명 · 사업종류 · 단계 · 세대수 · 구독 상태 |
| 구역 관리 | 데이터 격리 확인 · 마스터 계정 발급 · 계정 정지 · 구역 정지 |
| 홈 화면 관리 | 조감도 이미지 · 구역 명칭 · 주소 (폰 미리보기 포함) |
| 단계 · 일정 | 사업 단계 · 조합설립 인가일 · 이주 · 입주 목표 |
| 전역 법령 | 법률 · 시행령 · 시행규칙 · 조례 · 고시 (전 구역 공통) |

**구역 제원은 운영자가 고칠 수 없습니다.** 면적 · 세대수 · 최고층수는 고시 원문에서 뽑아 검산 23개 규칙을 통과한 값입니다. `4,003세대`는 분양 3,293 + 임대 710으로 맞아떨어지고, `179,566.0㎡`는 용도지역 면적 합계와 일치합니다.

손으로 고치면 검산이 깨지는데 조합원 앱에는 여전히 "검산 통과"라고 표시됩니다. **다알아의 가장 큰 강점이 거짓말이 되는 순간입니다.** 고치려면 고시 자료를 다시 올려야 합니다.

**전역 법령은 원문을 복사하지 않고 링크를 겁니다.** 전문을 저장하면 개정될 때마다 낡은 조문이 남습니다. 국가법령정보센터로 연결하면 항상 현행이 나오고, AI 답변에는 요약과 시행일을 씁니다. 여기서 고치면 전 구역 자료실에 동시에 반영됩니다.

### 권한 역할 분담

| 누구 | 계정 | 하는 일 |
|---|---|---|
| **운영진**(공급자) | 운영자 콘솔 | 조합장·총무이사에게 **마스터 계정만** 발급. 조합 요청 시 구역별 접근 개방. **조합 내부 권한 배분과 행정 판단에는 관여하지 않음** |
| **조합장·총무이사** | 마스터 계정 | 직원 계정을 **직접 만들고 권한을 정함**. 명부 변경 최종 승인 |
| **조합 직원** | 직원 계정 | 명부 업로드·수정. **단, 결재를 거쳐야 반영됨.** 모든 작업이 감사 로그에 기록 |
| **조합원** | 본인인증 | 휴대폰 인증 후 **명부와 실시간 대조**해 권한 자동 부여. 사람이 승인하지 않음 |

**운영진은 조합 명부를 열람하지 않습니다.** 운영자 콘솔에는 인원 수만 보이고 이름·연락처는 나오지 않습니다. 계정을 열어주는 일과 명부를 보는 일은 다릅니다.

### 명부 변경 · 전자결재 연동

**명부는 직원이 혼자 고칠 수 없습니다.**

```
직원이 수정 · 추가 · 삭제 · 일괄등록
      ↓ 자동 생성
[명부 변경 품의]  MBR-2026-000
      ↓
총무이사 검토 → 조합장 최종 승인
      ↓
그때서야 명부와 정족수 모수에 반영
```

승인 전까지 **원본이 그대로 남습니다.** 명부 화면 위에 `승인 대기 중인 변경 N건`이 뜨고, 확정 명부와 "모두 승인되면 몇 명이 되는지"를 나란히 보여줍니다.

**조합원 삭제는 근거 문서가 필수입니다.** 등기부등본·매매계약서·상속 서류 중 하나를 고르고 사유를 적어야 결재가 올라갑니다. 매매·상속으로 자격이 넘어가는 중대한 사안이고, 잘못 지우면 그분 의결권이 사라집니다.

**긴급 통로는 두지 않습니다.** 총회 당일이라도 정석대로 결재를 거칩니다. 긴급 통로를 열어두면 그것이 일상이 됩니다. 알림톡이 조합장 폰으로 즉시 가므로 승인은 30초면 끝납니다.

**투표 중에는 반영하지 않습니다.**

이미 표를 던진 분들은 지금 모수를 기준으로 행사하셨습니다. 도중에 의결권자가 97명에서 109명이 되면 그 표들의 기준이 달라지고, 가결·부결이 뒤집힐 수 있습니다. 소송이 나면 조합이 집니다.

승인은 받되 **적용은 투표 마감 뒤로 미룹니다.** 마감 후 `보류된 N건 지금 반영하기`를 누르면 한꺼번에 들어갑니다.

### 조합원 찾기

**이름 · 조합원번호 · 지번 아무거나** 넣으면 됩니다. 치는 대로 후보가 뜨고 고르면 끝납니다. 조회 버튼이 없습니다.

```
"18"          → 0009 황시희(지번) · 0018 조성은(번호)
"614-54"      → 0018 조성은(지번) · 0019 권선희(지번)
"조성은"       → 0018 조성은(이름)
```

**지번으로 찾는 게 실무입니다.** 조합원이 찾아와서 "저 614-54요"라고 하지 "18번이요"라고 하지 않습니다. **조합원번호를 아예 안 쓰는 조합도 많습니다.**

공유 필지로 찾으면 **두 분이 다 나오고** 대표/비대표가 표시됩니다. 필지가 여럿인 분은 **어느 필지로 찾아도** 나옵니다.

서면 접수 · 투표 입력 · 명부 조회 세 군데에 같은 방식이 걸려 있습니다.

**종이 제출일은 미래 날짜를 막습니다.** 연도를 잘못 넣는 실수가 흔합니다.

### 명부 구조 — 조합원과 소유 물건

**한 조합원이 여러 필지를 가진 경우가 흔합니다.** 한 줄에 물건 하나만 담으면 동의율 계산이 틀어집니다. 그래서 둘로 나눴습니다.

```
조합원(ROSTER)    번호 · 성명 · 연락처 · 대표조합원
소유 물건(PROPS)  번호 · 지번 · 지목 · 대지면적 · 지분 · 소유구분
```

**면적은 `대지면적 × 지분`을 다 더합니다.**

```
조합원 0018  →  62.0×1 + 30.0×0.5 + 12.2×1 = 89.2㎡
```

**세 가지를 반드시 구분해야 합니다.**

- **공유 지분** — 한 필지 100㎡를 둘이 반씩 가졌으면 각각 50㎡. 대표조합원이 100㎡를 다 가진 것으로 세면 안 됩니다
- **건물만 소유** — 남의 땅에 건물만 가진 분. **사람 수에는 들어가고 면적은 0**입니다
- **국공유지** — 도로·구거는 소유자가 지자체라 동의 대상이 아닙니다. 구역 면적에는 들어가지만 **동의 모수에서는 뺍니다**

### 사업 종류별 동의 요건

| 사업 | 조합설립 요건 |
|---|---|
| 주택재개발 | 토지등소유자 3/4 + **토지면적 1/2** |
| 주택재건축 | 구분소유자 3/4 + 동별 과반수 + **토지면적 3/4** |
| 사업시행 변경 | 조합원 과반수 (면적 요건 없음) |

운영자 콘솔에서 구역의 **사업 종류**를 바꾸면 요건이 자동으로 따라갑니다. 재건축은 면적이 3/4로 올라가 훨씬 까다롭습니다.

**동별 과반수도 계산합니다.** 물건에 `동`·`호수` 칸을 두었습니다. 재개발은 비워 두면 되고, 재건축 구역이면 동마다 따로 셉니다.

```
101동  29 / 17 (33세대)  충족
102동  29 / 17 (32세대)  충족
103동   0 / 17 (32세대)  미달   ← 여기서 막힘
→ 한 동 미달로 인가 불가
```

**한 동이라도 미달이면 전체 동의율이 아무리 높아도 인가가 나지 않습니다.** 화면에 동별 막대를 나란히 보여주고, 미달인 동만 골라 문자를 보낼 수 있게 안내합니다.

재건축 구역인데 동 칸이 비어 있으면 업로드 때 경고로 잡습니다.

**면적의 의미도 사업마다 다릅니다.** 재개발은 필지 면적, 재건축은 대지권 지분입니다. 넣는 자리가 같아 계산은 그대로 쓰고, 화면 이름만 `대지면적`/`대지권`으로 바뀝니다.

### 조합원 명부 · 엑셀 일괄 업로드

`admin.html` → `조합원 명부` (조합장 결재 후 열람)

```
1단계  CSV 서식 받기       열 이름은 바꾸지 말 것 · 순서는 무관
2단계  작성한 파일 올리기   검증 후 결과 확인
3단계  등록                 오류가 없어야 등록됩니다
```

**오류는 전량 차단합니다.** 정상 행만 넣으면 어디까지 들어갔는지 몰라 더 혼란스럽습니다. `오류 행만 엑셀로 받기`로 그 파일만 고쳐 다시 올리십시오. **경고는 막지 않습니다.**

**중복 처리 (B안)** — `기존 조합원 정보 갱신`을 켜면 같은 번호를 덮어씁니다. 덮어쓰기 전에 **무엇이 어떻게 바뀌는지** 표로 보여주고 확인을 받습니다. 꺼두면 중복은 오류로 막습니다.

**지분과 대표조합원이 핵심입니다.**

한 부동산을 부부나 형제가 나눠 가진 경우, 두 사람 다 명부에는 오르지만 **의결권은 대표 1인에게만** 있습니다.

```
명부 인원   100명   ← 화면에 다 보입니다
의결권자     97명   ← 전자투표 · 총회 정족수 · 설문 모수
```

전자투표·설문·집계가 모두 `VOTER_N()`을 모수로 씁니다. **`ROSTER.length`가 아닙니다.** 이걸 잘못 잡으면 정족수 계산이 통째로 틀립니다. 공유 물건인데 대표가 지정되지 않으면 업로드 때 경고로 잡습니다.

**개별 수정** — 명부 목록에서 `수정`을 누르면 아래에 편집 칸이 열립니다. 조합원번호·연락처 중복은 저장할 때 다시 검사합니다. 추가와 삭제도 됩니다.

서식 파일에는 **예시 두 줄만** 들어 있습니다. 실제 조합원 자료가 담긴 파일이 돌아다니는 것 자체가 사고입니다.

### 전자 설문조사

**설문은 전자투표가 아닙니다.** 섞으면 분쟁이 됩니다.

| | 전자투표 | 설문조사 |
|---|---|---|
| 효력 | 법적 의결권 행사 | 참고용 의견 수렴 |
| 근거 | 정관에 규정 필요 | 필요 없음 |
| 정족수 | 따집니다 | 없습니다 |
| 철회 | 철회신청서 · 조합장 결재 | 다시 제출하면 됨 |

응답 화면 맨 위에 **"법적 효력이 있는 의결이 아닙니다"** 경고가 고정돼 있습니다. 이게 빠지면 "설문에서는 반대가 많았는데 왜 통과됐냐"는 말이 반드시 나옵니다.

**문항 유형 여덟 가지** — 단일 선택 · 복수 선택 · 드롭다운 · 주관식 단답 · 주관식 장문 · 척도 1~5 · 날짜 · 숫자. 직원 화면에서 유형 버튼을 누르면 문항이 생기고, 보기는 `+ 보기 추가`로 얼마든지 늘립니다. 순서 이동 · 복사 · 삭제도 됩니다.

**양식 다섯 가지** — 총회 참석 사전조사 · 안건별 사전 의견 · 평형 선호도 · 이주 희망 시기 · 조합 운영 만족도. `처음부터 만들기`도 있습니다. **양식은 출발점일 뿐이고** 불러온 뒤 마음대로 고칠 수 있습니다.

**운영 방식 (확정)**

- **결과는 마감 후 공개합니다.** 진행 중에 결과가 보이면 나중에 응답하는 분이 여론에 휩쓸립니다.
- **답변은 익명, 참여 여부만 기록합니다.** `survey_answers`에는 이름을 남기지 않고 `survey_voters`에 참여 사실만 남깁니다. 둘을 분리해야 솔직한 답이 나오면서 1인 1회도 지켜집니다.

**정족수 판단까지 해줍니다.** 총회 참석 사전조사는 `직접 출석 예상 24명 · 필요 20명`처럼 견줘 보여주고, 여유가 없으면 독려하라고 알려줍니다. 단순 집계만 보여주면 직원이 직접 계산해야 합니다.

주관식은 **원문 그대로** 보여줍니다. 요약하면 조합원 목소리가 뭉개집니다.

### 화면 사이 자료 잇기

**직원 화면에서 올린 소식이 조합원 폰에 나갑니다.**

```
admin.html 에서 소식 등록
      ↓  Supabase app_state 테이블
index.html · 조합원 폰에 표시
```

브라우저 저장소만 쓰면 그 기기 안에서만 통합니다. 컴퓨터에서 올린 것이 폰에 가지 않습니다. **조합원 앱은 폰에서 보는 게 전부**라 그러면 의미가 없습니다. 그래서 서버에 담습니다.

**저장소는 화면을 빨리 띄우기 위한 임시 보관으로만** 씁니다.

```
① 화면 열림  →  저장소에 있던 것으로 곧바로 그린다
② 서버에서 받아온다  →  다르면 다시 그린다
```

서버가 느려도 화면이 비어 보이지 않습니다. 조합원 앱은 **20초마다 서버를 살펴** 보고 있는 중에 새 소식이 올라와도 알 수 있습니다.

**여기 담는 것은 어차피 공개되는 자료뿐입니다.** 소식·총회 안건·설문처럼 조합원 누구나 보는 것만요. **명부와 감정평가는 절대 담지 않습니다.**

`sql/009_app_state.sql`을 Supabase에서 한 번 실행하셔야 합니다.

### 소식과 자료의 기준

**시간이 지나면 어떻게 되는가**로 나눴습니다.

| | 성격 | 예 |
|---|---|---|
| 소식 | 지나가면 값이 없어지는 것 | 긴급 공지 · 총회 D-3 · 조합장 브리핑 |
| 자료 | 시간이 지나도 남는 것 | 고시문 · 정관 · 회의록 · 감정평가서 |

지나간 소식은 자료실로 넘어갑니다.

자료실은 여섯 분류입니다. **법령 · 정관/규정 · 고시문 · 감정평가서 · 회의록 · 회계/지출.** 지금은 고시문과 회계만 초록색이고 나머지는 `준비 중`입니다. **있는 것과 없는 것을 숨기지 않습니다.** 조합장께 자료를 요청할 때 이 화면이 그대로 근거가 됩니다.

### AI 자료실 검색 · 요약

**AI 키를 화면 파일에 두지 않습니다.** 이 화면은 정적 파일이라 서버가 없고, 키를 넣으면 누구나 소스를 열어 훔쳐 쓰며 요금은 조합에 청구됩니다.

대신 **이미 검산을 마친 고시 원장 65항목에서 답을 꺼냅니다.** AI가 문장을 지어내는 것이 아니라 확정된 숫자를 찾아오는 방식이라 오히려 틀릴 수가 없습니다. 답변에는 원문 페이지와 검산 통과 여부가 함께 붙습니다.

지금 답할 수 있는 주제는 용적률 · 세대수 · 임대주택 · 기반시설 · 층수/높이 · 용도지역 · 일정입니다. 정관 · 회의록 · 감정평가서는 **"아직 등록되지 않아 답할 수 없습니다"**라고 답합니다. **모르면 지어내지 않습니다.**

나중에 Supabase Edge Function에 키를 두고 거기서 AI를 부르면 자연어 질문과 회의록 요약이 진짜로 돌아갑니다. 결재 알림(`notify-approval`)과 같은 구조입니다.

### 회계 지출 집계

세 화면이 `archive-demo.js`의 같은 표를 봅니다.

```
전자결재에서 지출 품의 최종 승인
      ↓ 자동 등록 (집행 대기)
직원 화면 '회계 집계' → 실제 지급 후 [집행 완료]
      ↓
조합원 앱 자료 → 회계·지출 에 공개
```

**집행이 끝난 건만 집계합니다.** 결재만 나고 돈이 안 나간 건을 섞으면 숫자가 부풀려지고, 조합원이 통장과 대조했을 때 맞지 않습니다.

과목별 합계에서 항목을 누르면 상세가 나오고, 상세를 누르면 **연동된 품의서와 증빙 PDF**가 열립니다. "어디에 왜 썼는지"를 숨길 수 없게 만드는 것이 이 화면의 목적입니다.

`expense_ledger` 테이블로 옮기면 됩니다. 주요 컬럼은 `doc_no` · `item`(예산 과목) · `title` · `amount` · `payee` · `approved` · `paid` · `status`(approved/paid) 입니다.

### 인장날인 대장

조합 인감을 언제 · 어디에 · 몇 매 찍었는지 남기는 장부입니다. `approval.html` 왼쪽 메뉴의 **인장날인 대장**에 있습니다.

**두 갈래로 들어옵니다.**

| 경로 | 방법 |
|---|---|
| 일반 품의서 | 기안 화면의 `[조합인감 날인 필요]` 체크 → 최종 결재 시 자동 등록 |
| 날인 단독 품의 | `SEL` 분류의 **인감 날인 품의서** 양식 → 최종 결재 시 직행 등록 |

**결재 완료와 실제 날인은 다릅니다.**

```
최종 결재      → 대장에 '날인 대기'로 등록 (자동)
실제 도장 날인 → '날인 처리'로 일자 · 매수 · 날인자 기록 → '완료'
```

조합장은 폰으로 승인했을 뿐이고 인감은 사무실 금고에 있습니다. 결재 시각을 날인 일자로 적으면 대장이 사실과 달라지고, 감사에서 "이날 정말 찍었느냐"는 물음에 답할 수 없게 됩니다.

**반출 여부를 반드시 남깁니다.** 조합 인감을 사무실 밖으로 들고 나가는 것이 사고가 가장 많은 대목입니다.

기간 · 사용처 · 문서 분류로 걸러 볼 수 있고, `A4 출력`을 누르면 작성자 · 확인자 · 조합장 날인란이 붙은 감사 제출용 대장이 인쇄됩니다.

`seal_ledger` 테이블로 옮기면 됩니다. 주요 컬럼은 `seal_no` · `doc_no` · `place`(사용처) · `reason`(사유) · `kind`(인감 종류) · `count`(매수) · `carry`(반출) · `keep`(회수 문서) · `approved_at` · `sealed_at` · `sealer` · `status` 입니다.

### 결재 알림 (문자 · 카카오 알림톡)

`approval.html` 왼쪽 메뉴의 **알림 발송 이력**에서 확인합니다. 지금은 **시연 모드**라 실제로 발송하지 않고, 화면 오른쪽 아래 배너와 브라우저 콘솔(F12)에만 남습니다.

| 시점 | 받는 사람 |
|---|---|
| 기안 상신 | 2단계 결재자 (총무이사) |
| 중간 승인 | 다음 단계 결재자 |
| 최종 승인 | 기안자 (완료 알림) |
| 반려 | 기안자 (사유 포함) |
| 3일 미결 | 대기 중인 결재자 (1회만) |

- **알림톡이 실패하면 문자로 대체합니다.** 카카오톡을 안 쓰거나 채널을 차단한 분이 조합 임원 중에 꼭 있습니다.
- **밤 9시~아침 8시는 보류**했다가 아침에 보냅니다.
- **링크는 1회용이고 24시간 뒤 만료**됩니다. 문자는 남에게 전달되기 쉽습니다.

실제 발송에 필요한 SQL과 Edge Function은 **`supabase-notify` 폴더**에 있습니다. **그 폴더는 웹에 올리지 마십시오.** 서버에 붙이는 파일입니다.

조합원 화면의 회원가입은 지금 **아무 값이나 넣어도 통과**합니다. 시연용입니다.
