## 2. 무엇이 생겼나

관리자 → 상담사 관리 → 상담사 등록에 ★**토글 열 개**가 생겼습니다.
3열 격자 «밖», 활성 여부 아래입니다.

```
[🎨 내사주그림]  [🧭 진로적성]  [💖 궁합]  [🔮 내 사주와 운세보기]  [💍 결혼택일]
[🍼 출산택일]   [🏡 이사택일]  [📇 내 이름 정밀분석]  [👶 내 아이 명품작명]  [🃏 타로]

[전체 선택] [전체 해제]                                    n개 선택됨
```

⚠️ 차례는 ★대표님이 적어 주신 그대로입니다. 홈 카드 차례와 다릅니다.
⛔ 마음대로 정렬하지 마십시오.

## 3. ★왜 «열» 개인가 (열둘이 아니라)

```
서비스로 세면 ★열   · 화면으로 세면 ★열둘
   결혼택일 · 출산택일 · 이사택일은 ★화면을 «둘씩» 씁니다
   (PickWeddingV7 + check/page 등). ★같은 price_key 를 씁니다.
⇒ 상담사가 고르는 것은 «서비스» 이므로 ★열 개가 맞습니다.

⛔ 「합격운/취업운」은 ★서비스를 안 합니다 (45부 대표님 지시). 넣지 마십시오.
```

## 4. 🔴 ★key 는 price_key 입니다 — 배관이 «이미» 깔려 있습니다

```
토글에 담기는 값은 ★consult_prices 의 price_key 와 «똑같은» 값입니다.
   mulsang · career · couple · saju · wedding
   · birth · moving · naming · naming_baby · tarot

★그래서 새로 깔 배관이 «없습니다» —
   ConsultButton 이 이미 ★params.set('priceKey', priceKey) 로
   ★열두 화면 «전부» 에서 실어 보내고 있습니다.
   ⇒ consultant-select 는 그 값을 «받고 있지만 아직 안 읽습니다».
   ⇒ ★4차에 그 한 줄만 읽으면 거르기가 됩니다.

⛔⛔ ★SERVICE_SPECIALTIES 의 key 를 바꾸지 마십시오.
     consult_prices · ConsultButton 열두 곳과 «한꺼번에» 어긋납니다.
```

## 5. ⚠️⚠️ ★specialty 칸을 지우지 마십시오

```
🔴 ★손님 화면이 «아직» 이 칸을 읽습니다 —
   consultant-select:404  상담사 이름 «아래 한 줄» 로 나옵니다.
   (없으면 「명리 상담」으로 나옵니다)

⇒ 그래서 저장할 때 ★두 칸을 «함께» 채웁니다 —
   specialties  ★price_key 배열   ['saju','couple']      ← 거르기에 쓸 값
   specialty    ★사람이 읽는 한 줄  '내 사주와 운세보기 · 궁합'  ← 손님 화면용

⛔ 한쪽만 넣지 마십시오. specialties 만 넣으면 손님 화면 한 줄이 «빈칸» 이 됩니다.
⛔ SQL 에서 specialty 칸을 DROP 하지 마십시오.
```

## 6. ★함께 고친 곳 — 화면 «하나» 가 아닙니다

47부 교훈(「화면 하나만 보고 고쳤다가 세 번 되짚었습니다」)대로 전수로 세었습니다.

```
consultantData.ts       ★SERVICE_SPECIALTIES 열 개 · specialtyName · specialtyLabel
                        ★옛 SPECIALTIES 여덟은 «지웠습니다» [대표님 「버리고 갈음」]
ConsultantForm.tsx      ★select → 토글 열 개 · specialties 칸 추가
ConsultantManager.tsx   ★저장 (두 칸 함께) · 편집 불러오기 (null 이면 빈 배열)
ConsultantTable.tsx     ★목록 «세 곳» + CSV 내려받기
                        ⚠️ 안 고치면 목록에서 «빈칸» 으로 보였을 자리입니다
```

⚠️ ★편집 불러오기에 안전장치를 두었습니다 —
   옛 자료는 specialties 가 `null` 이라 그대로 들어오면
   `form.specialties.includes` 에서 ★터집니다. 빈 배열로 바꿔 넣습니다.

## 8. ⚠️ 아직 «안 한» 것 — 4차에 할 일

```
□ ★consultant-select 가 priceKey 를 «읽어» 거르기
     지금은 활성 상담사를 «전부» 보여줍니다.

⚠️ 거르기를 켤 때 ★생각하실 것 —

   ⇒ [대표님] 「관리자 페이지에서 고객 결과화면에 보여주는
      전문상담사 연결버튼을 ★보여줄지 말지를 결정하고 있으니 관계없어」
   ⇒ ★consult_prices.active 를 끄면 ★버튼 자체가 안 뜹니다 (ConsultButton:76).
      토글을 채우기 «전» 인 서비스는 그렇게 닫아 두십시오.
```
