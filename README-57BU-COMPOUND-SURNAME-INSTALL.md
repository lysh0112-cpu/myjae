## 2. 🔴🔴 «한 칸에 두 글자» 를 넣은 것이 «아닙니다»

여기가 이 작업에서 가장 조심한 자리입니다.

```
⛔⛔ next[0] = 南  ·  next[1] = 宮      ← ★이렇게 했습니다 (두 칸을 각각)
⛔⛔ next[0] = '南宮'                    ← ★이렇게 하면 안 됩니다
```

한 칸에 「南宮」을 넣으면 **획수가 19가 아니라 «두 글자짜리 한 글자»** 가 되어
수리 4격·자원오행이 통째로 어긋납니다.

★**칸은 그대로 둘입니다. 고르는 «횟수» 만 하나로 줄였습니다.**

⚠️ 28-verify 에 이것을 지키는 검사를 **새로 넣었습니다** —
`next[0] = toNameChar(a)` 다음에 `next[1] = toNameChar(b)` 가 오는지 봅니다.

---

## 3. ★값으로 확인한 것 — 판정은 «원래 맞고 있었습니다»

손대기 전에 먼저 쟀습니다.

```
/api/naming/route.ts:101
   const sp = splitSurname([body.surname, ...body.given])
   surname : sp.surname[0]
   surname2: sp.surname[1]
```

⇒ **API 가 이미 복성을 다시 가르고 있었습니다.** 수리 4격은 원래 맞았습니다.
⇒ ★틀렸던 것은 **화면 글자 하나**(「이름 1글자」)와 **고르는 횟수** 뿐이었습니다.

⚠️ 그래서 이번 손질은 **판정을 한 줄도 안 건드렸습니다.**
⛔ 여기서 성 가르기를 새로 짜지 마십시오. `splitSurname` 한 곳입니다.

## 4. ⚠️ 막지 않았습니다 — 못 찾으면 «낱글자» 로 내려갑니다

```
두 글자 가운데 ★하나라도 hanja 표에서 못 찾으면
   → 예전처럼 «낱글자» 고르기로 내려갑니다.
   ⛔ 막아 버리면 그 집안이 아예 못 넘어갑니다.
```

⚠️ 지금 걸릴 만한 자리 — **명임(明臨)의 臨**. 「임」 소리로 표에 있어야 합니다.
없으면 조용히 낱글자로 내려가니 **손님은 막히지 않습니다**.

## 5. ★검사 그물

기존 둘이 「`i > 0`」 이라는 **글자 그대로** 를 붙잡고 있어 걸렸습니다.
⛔ 느슨하게 풀지 않고 **새 모양으로 다시 조이고, 검사를 넷 더 넣었습니다.**

```
[고침]  const locked = i > 0        →  ★i >= surCount
        i > 0 이 있는가             →  ★i >= surCount 가 있는가

[새로 넣음]
  ★const surCount = compound ? 2 : 1 이 있는가   (복성이면 앞 두 칸이 성)
  ★pickCompound 가 있는가
  ⛔ 한 칸에 두 글자를 넣지 않고 «두 칸» 을 채우는가   ← ★가장 중요
  ★복성 목록을 화면에 다시 적지 않았는가 (「南宮」이 화면 파일에 없어야 합니다)
  ⚠️ 못 찾으면 낱글자로 내려가는가

⇒ 그물 통과 1,679 → ★1,684 (다섯 늘었습니다)
```
