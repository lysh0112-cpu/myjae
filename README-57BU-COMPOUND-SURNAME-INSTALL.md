## 1. ✅ 무엇이 바뀌나 — 두 화면 «같은 규칙»

```
[전]  남궁민수 →  「남」 창에서 南 고르고
                  「궁」 창을 다시 열어 宮 고르고        ★두 번
[후]  남궁민수 →  ★「南宮」 한 장을 누르면 두 칸이 함께 채워짐   ★한 번
```

카드 모양 —

```
   南宮    남궁 · 두 글자 성씨
           南 화·9획 / 宮 목·10획 → 성 19획
```

### ① 내 이름 정밀분석 (diagnosis)

```
· 「남」이든 「궁」이든 어느 칸을 눌러도 ★한 창으로 모입니다
· 창 문구 : 「두 글자 성씨예요. 한 번 누르면 두 글자가 함께 채워져요」
· ★덤으로 고쳐진 것 — 전에는 「궁」 칸 밑에 «이름 1글자» 라고 적혀 있었습니다.
  이제 두 칸 모두 ★「성(姓)」 입니다.
```

### ② 신생아 작명 · 개명 (newhanja)

```
· 성씨 칸에서 ★복성 카드가 «맨 위» 에 나옵니다
· 누르면 두 칸이 차고 ★곧바로 «첫 이름 칸» 으로 넘어갑니다
· ⚠️ 아래 낱글자 목록은 ★그대로 둡니다 —
     「집안에서 다른 한자를 쓰신다면 아래에서 한 글자씩 골라 주세요」
  ⛔ 낱글자 목록을 지우지 마십시오. 표기가 다른 집안이 못 넘어갑니다.
```

## 2. 🔴🔴 «한 칸에 두 글자» 를 넣은 것이 «아닙니다»

이 작업에서 가장 조심한 자리입니다.

```
diagnosis   next[0] = 南  ·  next[1] = 宮
newhanja    setChosen((prev) => ({ ...prev, 0: a, 1: b }))
                                              ↑ ★두 칸을 각각

⛔⛔ next[0] = '南宮'   ← 이렇게 하면 획수가 19가 아니라
                          «두 글자짜리 한 글자» 가 되어 수리 4격이 통째로 어긋납니다.
```

★**칸은 그대로 둘입니다. 고르는 «횟수» 만 하나로 줄였습니다.**

⚠️ 특히 newhanja 는 `chosen` 이 **«칸 번호»로** 담깁니다.
칸을 «있다 없다» 하게 만들면 번호가 밀려 **이미 고른 이름 한자가 성씨 자리로 옮겨 갑니다.**
⇒ ★`slots` 은 **한 줄도 안 건드렸습니다.**

## 3. ★값으로 확인한 것 — 판정은 «원래 맞고 있었습니다»

손대기 전에 먼저 쟀습니다.

```
/api/naming/route.ts:101
   const sp = splitSurname([body.surname, ...body.given])
   surname : sp.surname[0]  ·  surname2: sp.surname[1]
```

⇒ **API 가 이미 복성을 다시 가르고 있었습니다.** 수리 4격은 원래 맞았습니다.
⇒ ★틀렸던 것은 **화면 글자 하나**(「이름 1글자」)와 **고르는 횟수** 뿐이었습니다.

⚠️ 그래서 이번 손질은 **판정을 한 줄도 안 건드렸습니다.**
⛔ 성 가르기를 화면에서 새로 짜지 마십시오. `splitSurname` 한 곳입니다.

## 4. ⚠️ 막지 않았습니다 — 못 찾으면 «낱글자» 로 내려갑니다

```

   → 예전처럼 «낱글자» 고르기로 내려갑니다. ⛔ 막지 않습니다.
```
