# 3단계-d — 504 시간초과 긴급 고침

```
바뀐 파일 2개.  3단계-c 위에 덮어쓰십시오.
```

## 무엇이 있었나

3단계에서 `max_tokens` 를 3,500 → 12,000 으로 올린 것이 원인입니다.

```
HTTP 504  FUNCTION_INVOCATION_TIMEOUT
```

```
3,500 일 때   «잘리면서» 60초 안에 끝났습니다 (그래서 JSON 복구 코드가 있었습니다)
12,000 일 때  끝까지 쓰느라 60초를 넘겼습니다
```

★그리고 형제 라우트와 대조하니 이랬습니다. (교훈 DT)

```
/api/tongbyeon   maxDuration = 300     ← 잘 됩니다
/api/naming      maxDuration = 60      ← ★여기만 60 이었습니다
```

## 고친 것 셋

```
① maxDuration   60 → 300      형제 라우트와 같게
② max_tokens    12,000 → 7,000
     [실측] 5관점 × 3단 + 맺음말 ≒ 39문장 ≒ 2,150자 ≒ 3,200~4,300 토큰
            3,500 은 «딱 경계» · 12,000 은 세 배 · 7,000 이면 두 배 여유
③ 손님 화면 오류 문구를 우리말로
     전  「An error occurred with your deployment FUNCTION_INVOCATION_TIMEOUT icn1::t5sd2-…」
     후  「풀이를 쓰는 데 시간이 오래 걸려 도중에 끊겼어요. 잠시 뒤 다시 시도해 주세요.」
     ⚠️ 원문은 버리지 않고 console 에 남깁니다
```

## ⚠️ 그래도 안 되면 — 요금제입니다

Vercel 은 `maxDuration = 300` 을 적어도 **요금제 상한까지만** 줍니다.

```
Pro     300초까지 → 이 고침으로 해결됩니다
Hobby    60초까지 → 300 을 적어도 60초에서 끊깁니다
```

여전히 504 가 나고 **끊기는 시각이 60초쯤이면 Hobby 입니다.** 그때는 —

```
가) max_tokens 를 5,000 으로 더 내리고
    프롬프트의 「2~4문장」을 「2~3문장」으로 줄이기      ← 가장 빠릅니다
나) 관점을 나눠 부르기 (5관점 → 2~3회)                 ← 4단계 일
다) 스트리밍으로 바꾸기 (/api/tongbyeon 처럼)          ← 근본 고침
```

★가)는 제가 바로 만들어 드릴 수 있습니다. 말씀해 주십시오.
