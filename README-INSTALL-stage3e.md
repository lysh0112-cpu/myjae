## 1. ⚠️ 먼저 — 여섯 분류를 «일부러 비워 두었습니다»

지시서에 예시로 주신 30자를 덕암 자료와 대조했습니다.
**26자를 덕암이 «쓸 수 있다»(不用 아님) 고 판정했습니다.**

```
聖(성) 中吉   夏(하) 中吉   靜(정) 中吉   秋(추) 中吉   冬(동) 中吉   心(심) 中吉
盡(진) 中吉   蘭(란) 小吉   龍(룡) 小吉   雲(운) 小吉   春(춘) 小吉   雪(설) 小吉
霜(상) 小吉   菊(국) 小吉   萍(평) 小吉   佛(불) 小吉   仙(선) 小吉   帝(제) 小吉  …
```

**아주 흔한 이름 글자들입니다.** 「하」 이름에 夏 · 「성」 이름에 聖 · 「정」 이름에 靜.
켜는 순간 그분들의 글자가 뒤로 밀리고 배지가 붙습니다 — **덕암 판정을 우리가 뒤집는 것**입니다.

★그래서 **해설(글)은 그대로 두고 «글자 목록» 만 비웠습니다.**
연재쌤이 확정해 주시면 `specialAvoidData.ts` 의 Set 에 채우기만 하면 바로 돕니다.

```ts
export const SEASON_CHANGE_SET = new Set<string>([])   // ← 여기 채우면 켜집니다
```

⚠️ 채우실 때 반드시 «덕암 품격» 과 대조하십시오.


★**막지 않습니다.** 덕암이 中吉로 본 글자는 **흐리게도 하지 않고** 배지만 붙입니다.

## 3. 지시서 원안에서 고친 세 자리

### ① `hasPenalty` 와 `penaltyScore` 가 어긋났습니다

```ts
// 원안
return { hasPenalty: false, penaltyScore: 5, ... }   // ← 둘이 다릅니다
```

부르는 쪽이 어느 것을 믿을지 모릅니다. `hasPenalty` 를 지우고 `penalty > 0` 로 판단하게 했습니다.

### ② 첫 번째로 걸린 것에서 `return` 했습니다

한 글자가 둘에 걸릴 수 있습니다. **실제로 겹칩니다** —

```
壹 · 貳 · 參  =  «숫자» 이면서 «서열»
```

원안대로면 서열만 잡히고 숫자를 놓칩니다. → 걸린 것을 **전부** 모으고 감점을 합칩니다(상한 30).

### ③ 서열 검사가 «죽어 있습니다»

`context.birthOrder` 가 있어야 도는데 **이름 풀이 폼이 «몇째» 를 안 묻습니다.**

```
元 birthOrder 없음  →  감점 0     ★지금 상태
元 birthOrder 2     →  감점 25
```

지우지 않고 남겨 두었습니다. 폼에 필드가 생기면 그때 살아납니다.

⚠️ 켜실 때 **元(원)·長(장)·季(계)·次(차)** 가 아주 흔한 이름 글자라는 것을 보십시오.
「둘째인데 元 을 쓰면 감점」이 옳은지는 연재쌤 판단입니다.

## 4. 배지가 «두 축» 입니다

```
badge         不用 · 무거운 뜻        (덕암 축)
specialBadge  숫자 · 간지 · 동자이음   (특수 규칙 축)
```

한 글자에 둘 다 붙을 수 있습니다.

```
辰(진) 中吉   badge 없음 · specialBadge 「사주 충돌 주의」 · 감점 12 · 흐리지 않음
殺     不用   badge 「인명 권장 안 함」 + specialBadge 「다음자(살/쇄)」 · 감점 45
柳     中吉   둘 다 없음 · 감점 0
```
