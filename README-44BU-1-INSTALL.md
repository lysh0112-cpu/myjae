## 무엇을 고쳤나

### ① 🚨 결과 화면이 «남의» 보관함으로 가던 것

🔴 명품작명으로 들어와 결과를 본 뒤 보관함 버튼을 누르면 정밀분석 보관함이 열렸습니다.
   까닭 — 결과 화면(diagnosis)이 주소를 «붙박이» 로 들고 있었습니다.
   ⚠️ 그 화면은 «두 갈래를 다» 엽니다. 작명 기록도 여기서 다시 봅니다.
      그러니 붙박이면 «작명 손님은 반드시» 남의 보관함으로 갑니다.

★[이제] 갈래를 정하는 규칙을 «한 곳에만» 적습니다.

```
lib/saju/namingRecords.ts
  storageBranchOfKind(kind)   풀이 → diagnosis · 그 밖(개명·신생아) → naming
  NAMING_STORAGE_PATH         /naming/diagnosis-storage · /naming/naming-storage
  NAMING_STORAGE_LABEL        정밀분석 보관함 · 명품작명 보관함
```

결과 화면은 ① 기록의 kind → ② URL 의 `?from=` → ③ 정밀분석 순으로 봅니다.

⚠️ ②를 둔 까닭 — 기록은 «불러온 뒤» 라야 kind 를 압니다.
   그 사이에 손님이 버튼을 누르실 수 있어, 보관함이 기록을 열 때 갈래를 함께 보냅니다.
⚠️ **머리글 뒤로가기도 함께 고쳤습니다.** 나가는 문이 둘인데 하나만 고치면
   그리로 나간 분이 또 남의 보관함에 떨어집니다.
⚠️ 보관함 «거르기» 와 «같은 규칙» 입니다 (풀이인가 아닌가).
   두 곳이 갈리면 버튼이 데려간 보관함에 그 기록이 «없는» 일이 생깁니다.
⚠️ 옛 주소(`/naming/diagnosis/storage`)는 «그대로 살아 있습니다» — 다만 이제
   «가리키지» 않습니다. 북마크·마이페이지로 오시는 분만 그리 옵니다. (교훈 AM)

★검사가 「보관함 주소를 박아 넣은 자리 0개」를 셉니다. 붙박이가 다시 생기면 막힙니다.
