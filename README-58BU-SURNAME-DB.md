## 2. ⛔⛔ 왜 «값» 은 성씨 표를 정본으로 삼지 않는가

대표님 지시는 「성씨는 성씨 DB에서만」이고, 그대로 했습니다 — **다만 «무엇을» 성씨
DB에서 가져오는지를 갈랐습니다.**

```
★성씨 DB 가 정합니다   어느 한자가 «성씨인가» · 어느 것이 «앞에 서는가» · 복성 짝
★hanja 표가 정합니다   획수 · 자원오행 · 발음오행 · 품격

⚠️ ★품격(不用)은 성씨 표에 «안 담았습니다» [대표님 지시] —
   성씨는 «타고나는 것» 이라 「쓰지 마라」가 성립하지 않습니다.
   성씨 칸은 전부터 품격을 «안 걸렀습니다» (43부 23차).
⚠️ ★발음오행도 안 담았습니다 — 이름 «전체» 를 이어 봐야 나오는 값입니다.
```

값까지 성씨 표에 두면 **두 벌이 됩니다.** 그러면 이런 일이 납니다.

```
🔴 결정적인 자리 — 呂 (여·려)
     엑셀(deokam) : 자원오행 ★土 · 中吉
     hanja 표(DB) : 자원오행 ★水 · 不用
     ✅ 2026-08-09 ★대표님 확정 「수(水)로 보는 것이 일반적이다」
   ⇒ ★엑셀을 정본으로 삼으면 «대표님이 정하신 것이 뒤집힙니다».

🔴 그리고 이 엑셀에는 ★2026-08-12 새 책 대조가 «반영되어 있지 않습니다».
   (2,798자 대조 · 되살린 1,231자 · 4,160 → 5,392)
   ⇒ 값을 성씨 표에 두면 ★어제 하신 일이 성씨 자리에서만 덮입니다.
```

그래서 엑셀의 값은 `ref_*` 칸에 **참고용으로만** 담았습니다.
⛔ **`ref_*` 를 판정에 쓰지 마십시오.** 표 주석과 `COMMENT ON COLUMN` 에도 적어 두었습니다.

## 3. ★이 표가 무엇을 바꾸나

```

        ② surnameAllowed.ts 로 «걸러냅니다»
   ⇒ 성씨 목록이 «뿌리» 가 아니라 ★«거르개» 입니다.
     hanja 표에 줄이 «없으면» 목록에 있어도 ★조용히 사라집니다.
     (56부의 辻·鴌 이 그랬고, SQL 로 hanja 표에 글자를 넣어 막았습니다)

[뒤]   ① ★surname_hanja 가 «뿌리» — 보일 글자를 이 표가 정합니다
       ② hanja 표는 ★«값만» — .in('hanja', 목록) 으로 «한자로» 찾습니다
                                            ↑ ★소리로 안 찾습니다

⇒ 덤으로 ★두음 짝이 함께 풀립니다 —
  hanja='羅' 로 찾으면 「나 羅」 줄이든 「라 羅」 줄이든 «둘 다» 옵니다.
  ⚠️ 성씨 표 안의 두음 짝은 일곱입니다 : 劉 呂 李 林 柳 梁 羅
     ★엑셀에서는 羅 하나만 품격이 갈렸고, 획수·자원오행은 ★일곱 다 같았습니다.
```
