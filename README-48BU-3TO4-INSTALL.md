## 2. 3차 — 전문분야 토글 «열 개»

관리자 → 상담사 관리 → 등록 · 활성 여부 «아래» 에 토글이 생겼습니다.

```
[🎨 내사주그림] [🧭 진로적성] [💖 궁합] [🔮 내 사주와 운세보기] [💍 결혼택일]
[🍼 출산택일] [🏡 이사택일] [📇 내 이름 정밀분석] [👶 내 아이 명품작명] [🃏 타로]
[전체 선택] [전체 해제]                                       n개 선택됨
```

★key 는 ★`consult_prices` 의 price_key 와 «같은» 값입니다.
   ⇒ `ConsultButton` 이 이미 ★열두 화면 «전부» 에서 priceKey 를 실어 보냅니다.
   ⇒ ★5차에 `consultant-select` 가 그 한 줄만 읽으면 거르기가 끝납니다.
⛔ ★SERVICE_SPECIALTIES 의 key 를 바꾸지 마십시오. 열두 화면과 어긋납니다.
⚠️ 차례는 ★대표님이 적어 주신 그대로입니다. 홈 카드 차례와 다릅니다.

★왜 «열» 개인가 — 결혼·출산·이사택일은 화면을 «둘씩» 쓰지만
   ★price_key 는 하나입니다. 화면으로 세면 열둘, 서비스로 세면 ★열입니다.

## 3. 4차 — 별칭(호)

관리자 폼 «이름 바로 옆» 에 칸이 생겼습니다.

```
[이름 (본명 · 관리자만 봅니다)]  [별칭 (호) — 고객에게 보입니다]
                                  예: 청산
                                  → 고객 화면 — 청산 선생님
```

⚠️ ★비워 두면 «본명이 그대로» 나갑니다.
   지금 계신 네 분이 갑자기 「상담사」로 바뀌지 않도록 그렇게 두었습니다.
⛔ 빈 별칭을 '상담사' 같은 말로 바꾸지 마십시오. 대표님이 채우실 때까지의 자리입니다.

---

## 4. 🔴🔴 ★본명이 «새던» 곳이 «넷» 이었습니다

대표님은 「상담사를 고르는 화면」만 말씀하셨지만, 전수로 세어 보니
★본명이 손님에게 닿는 자리가 넷이었습니다. ★함께 막았습니다.

```
① consultant-select   상담사 고르기 목록 · 동그라미 첫 글자 · ★예약 완료 「○○ 선생님」
② mypage-new          ★내 예약 목록 · 예약 «취소 확인» 문구
③ consulting          상담 진행 화면 · ★채팅 제목 「○○ 상담사」 · 일정 고르기
④ api/summarize       ★「AI 정리 결과」 — «손님께 톡으로» 나가는 글에 이름이 들어갑니다
                      (③의 selected.name 을 타고 갑니다 — 함께 막혔습니다)
```

⇒ ★하나만 고쳤으면 「고르는 화면은 청산 선생님인데
   마이페이지·채팅·톡에는 본명」이 되었을 것입니다.

### ★lib/consultantName.ts — 한 곳에서 정합니다

```ts
shownName(c)   // 별칭이 있으면 별칭, 없으면 본명
```

⚠️⚠️ ★손님 화면에서는 «언제나» 이것을 쓰십시오. ⛔ `c.name` 을 직접 쓰면 ★본명이 샙니다.
⚠️ 조회에도 ★`alias` 를 «반드시» 넣으십시오 — `select('id, name, alias, …')`.
   빠뜨리면 `alias` 가 undefined 라 조용히 ★본명이 나갑니다. 아무도 모릅니다.
⛔ ★관리자 화면·상담사 본인 화면에는 쓰지 마십시오. 그쪽은 본명이 보여야 합니다.

⚠️ ★`admin/components` 가 아니라 `lib` 에 두었습니다 —
   손님 화면이 «관리자 폴더» 를 들여오면 안 됩니다.
